# Metrics

Generated views of the TOML detection collection. These reports describe metadata and ATT&CK mappings; they do not measure recall, false-positive rate, sensor availability, or operational coverage.

## Files

| File | Description | Generated by |
|---|---|---|
| [detectiondata.csv](detectiondata.csv) | Inventory of detection names, original authors, severity, and mappings | `toml_to_csv.py` |
| [navigator.json](navigator.json) | ATT&CK Navigator layer, scored by rule mappings | `toml_to_navigator.py` |
| `recentdetections.md` | Rules created in the current and previous two months | `toml_to_md.py` |
| `latestdetections.md` | Monthly creation report | `toml_to_report.py` |

Creation reports use the original `metadata.creation_date`. Historical rules should not be redated to make them appear new, so an empty recent-month table is expected when no rules were created during that period.

## ATT&CK Navigator

Import [navigator.json](navigator.json) into [MITRE ATT&CK Navigator](https://mitre-attack.github.io/attack-navigator/). A score counts rules mapped to that technique and tactic. Several rules mapped to a technique do not establish that the technique is fully covered.

## Regenerating Metrics

Run from the repository root after validating the source rules:

```bash
python development/validation.py
python development/toml_to_csv.py
python development/toml_to_navigator.py
python development/toml_to_md.py
python development/toml_to_report.py
```

The scripts write under `metrics/` by default. See [development usage](../development/README.md) for output options. Review and commit intentional inventory changes; the workflow does not force-push generated changes to your branch.
